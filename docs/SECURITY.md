# Security model

DevTeleport keeps source data local. Snapshots stay encrypted during file transfer. Long unique passphrases are required; no password recovery exists. Environment credentials can be inspected by privileged local processes, so interactive hidden input is preferred. Derived key buffers are cleared after use; JavaScript strings and copies cannot be guaranteed erased.

The reader authenticates before decompression, bounds expansion/counts/payloads and validates version, paths, types, modes, sizes and checksums. It rejects traversal, ambiguous separators, duplicates, case collisions, unsafe parents and escaping/chained/dangling links. Git configuration, hooks, external object alternates and internal Git links are not restored. Git subprocesses used for analysis/verification disable hooks/fsmonitor and global configuration to prevent code execution during inspection.

Known credential paths and high-confidence private-key/AWS/GitHub token patterns are omitted with explicit records. Git history, arbitrary embedded secrets, settings, databases and explicitly selected volume data can still contain credentials. This is not universal detection. Review contents and treat the encrypted archive as sensitive. Database/volume payloads are opt-in, not automatically scrubbed.

Default restore neither installs packages nor starts services. Dependency approval permits npm lifecycle scripts; database approval permits executable SQL; Compose approval permits container execution including privileges requested by reviewed Compose files. Review provenance first. PostgreSQL permits only explicit localhost development URLs and rejects production-like names, but cannot identify production port forwards. It uses external destination mapping and inherited libpq override removal. Versions are checked and nonempty targets refused; source/files/databases are not one distributed transaction.

Named-volume backup requires stopped containers and a plain local driver without options. Helpers mount only the selected volume, never host paths or the Docker socket, and have no network and a read-only root. DAC/CHOWN capabilities are narrowly enabled for file access/ownership. Python's safe extraction filter rejects escaping symlinks and special/unsafe paths, strips privilege bits and enforces expansion limits. Restore creates a randomly labeled volume and refuses any preexisting destination. Docker administrators and the Docker daemon are trusted local principals.

AES-GCM authenticates relative to the passphrase, not an author identity. Optional Ed25519 signatures use externally trusted public keys; generated private keys are encrypted PKCS8 files with restrictive permissions. Transfer the `.sig` sidecar along with the archive. Local inventory verification is convenient but mutable; use verification against the original authenticated snapshot for stronger evidence. Signatures do not make arbitrary source, SQL or Compose instructions safe to execute.

Atomic no-clobber capture publication protects final names. Recovery journals and read-only inspection expose incomplete restore stages; cancellation/crashes are not cross-component rollback. Existing destinations are never deleted to resolve an error. The source and destination parents must be trusted; hostile local writers, kernel attacks and active filesystem race attackers are outside this release's boundary.

Limits: 128 MiB aggregate decoded project/database/compressed-volume data; 32 MiB per file/dump/compressed volume; 50,000 project entries; 256 MiB expanded JSON; each volume has 128 MiB expanded-data/50,000-member limits. Base64, compression and double reads amplify memory usage. Larger streaming format work is separate.

No independent security audit, OS code signing/notarization, universal secret detection, production-database discovery, live process migration or authenticated peer network protocol is claimed. Application signing credentials were unavailable; local installers remain unsigned.
