# Security model

DevTeleport keeps source data local. Snapshots stay encrypted during file transfer. Long unique passphrases are required; no password recovery exists. Environment credentials can be inspected by privileged local processes, so interactive hidden input is preferred. Derived key buffers are cleared after use; JavaScript strings and copies cannot be guaranteed erased.

The reader authenticates before extraction (and before decompression for format 1), bounds expansion/counts/payloads and validates version, paths, types, modes, sizes and checksums. It rejects traversal, ambiguous separators, duplicates, case collisions, unsafe parents and escaping/chained/dangling links. Git configuration, hooks, external object alternates and internal Git links are not restored. Git subprocesses used for analysis/verification disable hooks/fsmonitor and global configuration to prevent code execution during inspection.

Known credential paths and high-confidence private-key/AWS/GitHub token patterns are omitted by default with explicit records. Current development source offers an explicit **Include ignored files & secrets** capture option (`--include-ignored`) that bypasses Git/default exclusions and embedded-credential filtering inside the chosen workspace. It can include real `.env`, dependency folders and local credential files. Capture/restore reviews warn about this; previews show names and metadata, not file bodies. Additional user exclusions and protected Git/DevTeleport metadata, size and safe-path rules still apply. This choice is not saved as a preference. See [INCLUDE-IGNORED.md](INCLUDE-IGNORED.md).

Git history, arbitrary embedded secrets, settings, databases and explicitly selected volume data can contain credentials even in ordinary captures. This is not universal detection. Review contents and treat the encrypted archive as sensitive. Share opt-in sensitive snapshots only with trusted recipients. Database/volume payloads are opt-in, not automatically scrubbed.

Default restore neither installs packages nor starts services. Dependency approval permits npm lifecycle scripts; database approval permits executable SQL; Compose approval permits container execution including privileges requested by reviewed Compose files. Review provenance first. PostgreSQL permits only explicit localhost development URLs and rejects production-like names, but cannot identify production port forwards. It uses external destination mapping and inherited libpq override removal. Versions are checked and nonempty targets refused; source/files/databases are not one distributed transaction.

Named-volume backup requires stopped containers and a plain local driver without options. Helpers mount only the selected volume, never host paths or the Docker socket, and have no network and a read-only root. DAC/CHOWN capabilities are narrowly enabled for file access/ownership. Python's safe extraction filter rejects escaping symlinks and special/unsafe paths, strips privilege bits and enforces expansion limits. Restore creates a randomly labeled volume and refuses any preexisting destination. Docker administrators and the Docker daemon are trusted local principals.

AES-GCM authenticates relative to the passphrase, not an author identity. Optional Ed25519 signatures use externally trusted public keys; generated private keys are encrypted PKCS8 files with restrictive permissions. Transfer the `.sig` sidecar along with the archive. Local inventory verification is convenient but mutable; use verification against the original authenticated snapshot for stronger evidence. Signatures do not make arbitrary source, SQL or Compose instructions safe to execute.

Atomic no-clobber capture publication protects final names. Recovery journals and read-only inspection expose incomplete restore stages; cancellation/crashes are not cross-component rollback. Existing destinations are never deleted to resolve an error. The source and destination parents must be trusted; hostile local writers, kernel attacks and active filesystem race attackers are outside this release's boundary.

Format 2 streams project/database bodies with 16 GiB per-file and 32 GiB aggregate limits, 16 MiB metadata and 50,000 entries. Authenticated plaintext staging is private and removed on handled completion; abrupt crashes can leave private plaintext requiring approved recovery cleanup. Format 1 retains 128 MiB aggregate decoded payload and 32 MiB per-payload limits, with 256 MiB expanded JSON. Named volumes retain 32 MiB compressed/128 MiB expanded/50,000-member limits. See [format details](FORMAT-2.md).

No independent security audit, OS code signing/notarization, universal secret detection, production-database discovery, live process migration is claimed. TLS 1.3 transfer uses explicit pairing, certificate verification, a protected bearer descriptor, expiry and resumable encrypted uploads; see [network security boundaries](NETWORK-TRANSFER.md). Application signing credentials were unavailable; local installers remain unsigned.
